# Divergences from upstream

This fork derives from mattpocock/skills, imported at upstream commit 4ae2317 on 2026-11-12 and carried verbatim in fork commit 43dd672. Derivation is one-directional: upstream updates are imported here periodically, never the reverse. This file lists every live divergence with its reason, one entry per divergence. A skill edit updates its divergence's entry or adds one, and an entry is removed only if the fork re-adopts upstream's behavior. The list is what makes each import a deliberate act: at import time the fork's differences are already named, so an upstream diff sorts into his new work, a divergence to defend, or drift to undo.

Latest import: upstream commit 5863806, examined 2026-11-16. Nothing was carried: every difference in the carried skills is fork-side, so every entry below is live.

## The fork's shape

- The docs/ directory carries the whole agent workflow (tracker, glossary, ADRs, rejected-request KB), committed to git. Upstream keeps the glossary at a root GLOSSARY.md, issues in a dot-prefixed .scratch/ directory, and the rejected-request KB in .out-of-scope/, all invisible to a gitignore that excludes dot-prefixed paths.
- Skill folders sit flat at skills/<name>/ instead of upstream's skills/<category>/<name>/, and upstream's category READMEs are not carried. The skills CLI discovers skills up to three levels deep, so the flat layout installs the same way.
- Skill names are kept from upstream so upstream changes stay visible during imports. Two renames: the router, ask-matt is ask-skills here, rewritten for the docs/ flow (PHASE-BOUNDARIES.md carried unchanged); and setup-matt-pocock-skills, carried as setup-agent-docs and restructured (entry under Carried skills, edited).
- Upstream's in-progress and misc skills (chief-of-staff, claude-handoff, loop-me, setup-ts-deep-modules, writing-beats, writing-fragments, writing-shape, git-guardrails-claude-code, migrate-to-shoehorn, scaffold-exercises, setup-pre-commit) are deliberately not carried: this fork ships the standard engineering set only. software-factory is additionally unadoptable as-is: its SKILL.md frontmatter fails upstream's own YAML parse.
- Carried skill files follow the writing standard's formatting rules (plain ASCII): arrows render as -> and ellipses as ... where upstream uses Unicode arrows and ellipses (to-tickets' publish bullets; ask-skills' rewrite follows the same rule).
- Disposable working files and the upstream import's comparison install live in the gitignored docs/tmp/ directory; upstream has no counterpart convention (its disposable working files historically landed in .scratch/).
- The MIT license file is carried as LICENSE.md rather than upstream's LICENSE.

Upstream says "save it where the repo already keeps such notes" with no convention; this fork defines one (ADR 0008).

- improve-codebase-architecture: the glossary path follows docs/agents/domain.md and ADRs stay at docs/adr/ (upstream reads a root GLOSSARY.md); the subsystem-spec orientation input was removed with promotion (ADR 0008).
- implement and implement-spec: a cleanup invocation added at the end (upstream has none): the finished feature's tracker state is removed by the cleanup skill once its tickets resolve (ADR 0008); otherwise upstream-verbatim, implement-spec's pointer renamed to /setup-agent-docs.
- code-review: the spec-source search names the feature spec by the tracker path the tracker doc defines, docs/tasks/<feature>/spec.md by default (upstream: a spec file under docs/, specs/, or .scratch/ matching the branch or feature); the subsystem-spec source and the promotion-consistency check were removed with promotion (ADR 0008).

- setup-agent-docs (upstream's setup-matt-pocock-skills, renamed so upstream changes to it stay visible during imports): same prompt-driven process, restructured for this fork: the local markdown tracker is the recommended default (upstream proposed GitHub first), the local tracker seed is rewritten for the committed docs/tasks/ layout with wayfinding operations, a freeform tracker seed is added, docs/agents/domain.md is emitted in a single- and a multi-context variant with only the chosen one written, the triage-labels table's column header is unbranded ("Canonical role"), a git policy section (Section D) and a versioned, delimited writing-standard block (v2) are added, and the description gains "git policy, and writing standard". The domain seed variants drop the subsystem-spec pointer and the precedence rule, the local tracker seed's layout gains the feature research/ directory and the containment invariant (nothing outside a feature's directory references inside it) while dropping the cross-feature blocker reference, and the research-location text describes the docs/tmp/ placement (ADR 0008).

## Fork-authored skills

- cleanup: new; upstream has no counterpart. Removes finished work's local tracker state once its tickets resolve (ADR 0008): implement and implement-spec invoke it inline, it runs standalone as a sweep with confirmation, it verifies the containment invariant (nothing outside a feature's directory references inside it) before every removal, and it protects the glossary, ADRs, and rejected-request KB. Unlike update-engineering-skills it ships in default installs: every project using the local tracker accumulates state.
- update-engineering-skills: new; upstream has no counterpart. Installs upstream side-by-side in the gitignored docs/tmp/ directory, diffs skills/ against it, attributes every difference from fork history (the foundation commit holds the verbatim import) with a raw fetch of the recorded upstream commit as the fallback baseline, and applies the confirmed import to skills/ and this ledger. Carries metadata.internal: true: it serves this repository's maintenance, so default installs never pick it up. (The former update-agent-docs, fork-authored with no upstream counterpart, was consolidated into setup-agent-docs in 2026-11; ADR 0007 records it, so no live entry remains.)
